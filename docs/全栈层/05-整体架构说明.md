# AI 视频剪辑智能体 — 全栈层整体架构说明

> 版本：v1.0 · 日期：2026-10-23
> 定位：技术架构总纲。PRD 定「做什么」，本文档定「怎么做」；冲突时以 PRD 为准
> 拍板记录（2026-10-23，用户确认）：**1a 测试策略 = eager 为主 + 真队列冒烟；1b 取消机制 = DB 查询态；本机暂无 Redis，真队列冒烟后补**

## 1. 拓扑（目标态）

```
Frontend ──► FastAPI API Layer ──► Celery Broker (Redis) ──► Worker (ffmpeg, prefork)
                 │                                                │
                 ▼                                                ▼
           SQLite / Postgres                              MinIO / 本地 FS
```

- 第一步（现状）：API 层 + ThreadPoolExecutor(1) 占位 + SQLite + LocalStorage
- 第二步（本次）：Celery + Redis 替换占位执行器；SQLite 升级 SQLAlchemy
- 第三步：ffmpeg 进度流式解析 + 两步杀进程流式取消
- 第四步：webhook 回调 + MinIO（Storage 抽象切换，上层零改动）

## 2. 分层职责

| 层 | 模块 | 职责 | 约束 |
|---|---|---|---|
| 核心库 | `ai_video_agent/`（compiler/operations/registry/render/timeline） | 纯函数：timeline → 校验 → ffmpeg 出片 | **全栈层零改动**；registry 是操作能力单一真相 |
| API 层 | `server/app.py` | 路由、请求校验、任务创建/查询/取消 | 不含渲染逻辑 |
| 状态机 | `server/state.py` | TaskState 六态 + TRANSITIONS 流转表 | 越态 = bug |
| 持久层 | `server/models.py` | render_tasks DAL（sqlite3 → SQLAlchemy） | 表结构与字段名不变 |
| 存储 | `server/storage.py` | Storage 接口 + LocalStorage | 切 MinIO 零改动上层 |
| 执行 | `server/executor.py` → Celery task | 状态推进：RUNNING → compile 预检 → render → storage.save → SUCCESS | 异常全落 FAILED + error_msg |

## 3. 关键接口签名（第二步迁移锚点）

```python
executor.submit(task_id, timeline_json)   →  render_video.delay(task_id, timeline)
executor.request_cancel(task_id)          →  删除（DB 查询态，API 直接写库）
executor._run(task_id, timeline_json)     →  Celery task 函数体（状态推进原样迁移）
ThreadPoolExecutor(1)                     →  celery -Q render --concurrency=1（prefork）
```

`_run` 内部为纯状态推进：`RUNNING → Timeline.from_dict → compile 预检 → render → storage.save → SUCCESS`，三个软取消检查点（render 前/后、入库前），临时目录用后即清。

## 4. 已拍板设计决策（ADR 摘要）

### ADR-1 测试策略：eager 为主 + 真队列冒烟（拍板 2026-10-23）

- **决策**：pytest 配置 `task_always_eager=True` 为主；另写 1–2 条真队列冒烟测试，`@pytest.mark.skipif(not REDIS_AVAILABLE)` 自动跳过
- **理由**：CI 零外部依赖、Windows 本机无 Redis 不阻塞开发、回归快符合「任何改动后必跑全量」铁律
- **盲区兜底**：eager 不覆盖 broker 序列化 / `acks_late` / `reject_on_worker_lost`，由真队列冒烟测试兜住（本机装 Redis 或 WSL 后补跑）
- **后果**：冒烟测试在无 Redis 机器上显示 skipped，属预期，不算回归

### ADR-2 取消机制：DB 查询态（拍板 2026-10-23）

- **决策**：`request_cancel` 语义 = API 把 DB `state` 置为 `CANCELLED`；worker 检查点查 DB。不引入 Redis 标志位，不用 Celery revoke
- **理由**：零新增依赖面；多 worker 天然安全；取消意图持久（worker 重启不丢）；优雅落库符合软取消语义；与现有 `_shortest` 降级的务实风格一致
- **已知代价**：取消延迟 = 检查点间隔，render 中段无法即时中断 → 由第三步两步杀（`proc.terminate` → `proc.kill`）解决，与取消信号通道解耦
- **代码迁移点（已实施）**：`executor.py` 删除；`app.py::cancel_task` 只写 DB；任务体在**四处检查点**查 DB —— **出队 / render 前 / render 后 / 入库前**
- **实施坑（已修复）**：worker 出队后立即写 `RUNNING` 会抹掉 API 预先写入的 `CANCELLED` → 出队检查必须先于 RUNNING 写入（任务体检查点 0）

### ADR-3 超时衔接语义（本文明确定义，消除模糊项 #6）

```
soft_time_limit = 540s  →  Celery 抛 SoftTimeLimitExceeded
                          → 任务体 except 捕获 → 落 TIMEOUT + error_msg（优雅路径，主路径）
time_limit      = 600s  →  硬杀兜底（worker 进程级）
                          → acks_late=True + reject_on_worker_lost=True → 任务重回队列
                          → 防死循环：任务体入口检查 created_at 距今 > 600s → 直接落 TIMEOUT，不再渲染
```

## 6. 第三步实施记录（已达成）与第四步范围

### 第三步：ffmpeg 进度解析 + 流式取消（✅ 2026-10-23）
- **render.py 钩子化**：keyword-only `on_progress / cancel_check / poll_interval / timeout`，
  Popen + stderr 读线程解析 `time=`（metadata.duration → clips 最大 out 点兜底为分母），
  既有调用方零改动
- **两步杀**：terminate → 宽限 5s → kill；取消时 rmtree 运行目录清半成品
- **任务体接入**：progress ≥1s 节流写库；render 返回 None 先查取消再落 FAILED；
  取消延迟从「检查点间隔」降至 ~1s
- 关键坑：Timeline 无顶层 duration，API 样例顶层 duration 被 from_dict 忽略

### 第四步：webhook + MinIO（✅ 2026-10-23）

## 8. 本机环境备忘（踩坑记录）

1. pip / pip-compile 必须显式 `--index-url https://pypi.org/simple`（tuna 对 pip JSON API 失效）
2. 锁文件必须 `--generate-hashes`（CI 用 `--require-hashes` 安装）
3. venv 一律项目内 `.venv`，禁占 C 盘；ffmpeg 仓库自带（`tools/ffmpeg/bin`）
4. Windows + Git Bash；GitHub 推送走 SSH（偶发瞬时认证失败，重试即可）
5. 测试造数据用 lavfi（`color=` / `sine=` / `hstack`）；cancel 类测试用 ≥5s 素材（1s 渲染太快，cancel 到达前可能已 SUCCESS）
6. **本机暂无 Redis**（拍板确认）：真队列冒烟测试 skipif 跳过；如需补跑，安装 WSL Redis 或 Memurai

## 9. 协作流程约定

- 迭代节奏：一次一个子任务，实现 → 全量回归 → commit → 推送 → 交审阅（发现问题直接修）
- 提交信息：`feat(scope): 描述，零回归` + 要点 + 末尾 `回归：N passed + N subtests`
- 外部审阅者通过上传文件审阅，每次交付附齐涉及文件
- 高危区「单测对、组合错」：每加一个能力，跑一次组合端到端
